# 목(mock) 서버 적용 가이드

> **대상:** 이 스캐폴드로 개발하는 프론트 개발자 전부. 공통 개발자·업무 개발자 모두 해당한다.
> **한 줄 요약:** **스캐폴드에는 목 서버가 없다.** 필요한 프로젝트가 §6 을 보고 설치한 뒤, 핸들러를 하나씩 늘려 쓴다.

MSW(Mock Service Worker)가 브라우저에서 요청을 가로채 가짜 응답을 만들어 준다.
서버가 아직 없거나, 서버 API가 아직 안 나왔거나, 인터넷이 막힌 환경에서도 화면 개발을 계속하기 위한 장치다.

## 30초 요약

```
지금 상태        스캐폴드에 목 서버가 없다. 쓰려면 먼저 설치한다 (6장)

설치한 뒤, 내 API 를 목에 추가하려면 (3단계)
  1) src/mock-server/handlers/<이름>.ts 에 핸들러를 쓴다
  2) src/mock-server/handlers/index.ts 에 등록한다
  3) 저장하면 반영된다 (안 먹으면 새로고침)

경로는 반드시 "/api" 로 시작한다.
  화면 코드 useApi('/orders')  ->  실제 요청 /api/orders  ->  핸들러도 '/api/orders'
```

목에 등록하지 **않은** 경로는 그대로 실서버로 나간다(`onUnhandledRequest: 'bypass'`).
그래서 "일부만 목, 일부는 실서버"가 자연스럽게 된다.

## 1. 언제 쓰고, 언제 쓰지 않나

| 이럴 때 쓴다 | 이럴 때 쓰지 않는다 |
|---|---|
| 서버 API 가 아직 안 나왔는데 화면을 먼저 만든다 | 실서버 API 가 이미 동작한다 |
| 인터넷·업무망이 막힌 자리에서 개발한다 | 성능·부하를 확인해야 한다 (목은 네트워크가 아니다) |
| 에러 응답(500, 403, 지연) 화면을 만들어야 한다 | 서버 쪽 로직 자체를 검증해야 한다 |
| 서버가 잘 만들어 주지 않는 상태(빈 목록, 페이지 끝)를 재현한다 | 운영 빌드 (목은 운영 번들에 아예 안 들어간다) |

### 스캐폴드가 목을 기본 제공하지 않는 이유

한때 인증 목과 예제 데이터 목이 기본으로 들어 있었지만 지금은 없다. 이유는 셋이다.

1. **프로젝트마다 규약이 다르다.** 특히 인증은 그대로 쓰인 적이 없어, 반입한 프로젝트가
   가장 먼저 하는 일이 그걸 지우는 일이 됐다.
2. **실서버를 가린다.** 목이 실서버와 같은 경로를 들고 있으면, 서버가 붙은 뒤에도 조용히 앞을 가린다.
   "분명히 붙였는데 옛날 값이 온다" 는 원인 찾기 어려운 버그가 여기서 나온다.
3. **첫 실행 경험.** 기본으로 켜져 있으면 스캐폴드를 처음 받은 사람이 자기 화면 대신
   남의 데모를 먼저 만난다.

그래서 목은 **필요한 프로젝트가 필요할 때 설치하는 것**으로 바뀌었다(§6).
설치했다면 **실서버가 뜨는 즉시 지운다**(§10).

**스캐폴드를 갓 받은 상태라면 적용돼 있지 않다.** 누군가 설치했는지 확인하려면 셋을 본다.

| 확인할 것 | 위치 |


없다면 → **6장(새로 설치하기)** 으로 간다.

## 3. 내 업무 API 를 목에 추가하기

이 문서에서 제일 많이 쓸 장이다.

### 3.1 먼저: 경로 규칙

가장 흔한 실수는 경로를 `/orders` 로 적어 놓고 "목이 안 먹는다"고 하는 것이다.
**핸들러 경로는 브라우저가 실제로 쏘는 최종 URL 이어야 한다.**

```
.env 의 VITE_API_BASE_URL      /api
화면 코드                       useApi('/orders')
브라우저가 쏘는 실제 요청        /api/orders
핸들러에 적어야 할 경로          '/api/orders'      <- 여기
```

> `VITE_API_BASE_URL` 을 바꾸면 핸들러 경로도 같이 바꿔야 한다.
> 인증 핸들러가 `const BASE = '/api/auth'` 를 파일 맨 위에 상수로 빼 둔 이유가 이것이다.

### 3.2 핸들러 파일 만들기

`src/mock-server/handlers/orders.ts`

```ts
import { http, HttpResponse } from 'msw';

/** 최종 경로 = .env 의 VITE_API_BASE_URL(/api) + 업무 경로 */
const BASE = '/api/orders';

const orders = Array.from({ length: 23 }, (_, i) => ({
	id: i + 1,
	orderNo: `ORD-2026-${String(i + 1).padStart(4, '0')}`,
	customer: `고객 ${i + 1}`,
	amount: (i + 1) * 1000,
	status: i % 3 === 0 ? 'DONE' : 'READY',
}));

export const orderHandlers = [
	// 목록
	http.get(BASE, () => HttpResponse.json(orders)),

	// 단건 — 경로 파라미터는 params 로 받는다 (값은 항상 string)
	http.get(`${BASE}/:id`, ({ params }) => {
		const found = orders.find((o) => o.id === Number(params.id));
		if (!found) {
			return HttpResponse.json({ message: '주문을 찾을 수 없습니다.' }, { status: 404 });
		}
		return HttpResponse.json(found);
	}),

	// 등록
	http.post(BASE, async ({ request }) => {
		const body = (await request.json()) as Record<string, unknown>;
		return HttpResponse.json({ ...body, id: orders.length + 1 }, { status: 201 });
	}),
];
```

### 3.3 등록하기

`src/mock-server/handlers/index.ts` 에 한 줄씩 더한다.

```ts
import { authHandlers } from './auth';
import { exampleHandlers } from './example';
import { orderHandlers } from './orders'; // <- 추가

export const handlers = [...authHandlers, ...exampleHandlers, ...orderHandlers];
```

저장한 뒤 브라우저를 새로고침하면 반영된다(서비스워커가 핸들러 목록을 다시 받는다).

> **순서 주의** — 배열 앞에 있는 핸들러가 이긴다.
> `/api/orders/:id` 를 `/api/orders/summary` 보다 앞에 두면 `summary` 요청이 `:id` 로 잡혀 버린다.
> **구체적인 경로를 먼저** 둔다.

## 4. 자주 쓰는 레시피

### 4.1 쿼리스트링 (검색·페이징)

```ts
http.get('/api/orders', ({ request }) => {
	const url = new URL(request.url);
	const page = Number(url.searchParams.get('page') ?? 1);
	const size = Number(url.searchParams.get('size') ?? 10);
	const keyword = url.searchParams.get('keyword') ?? '';

	const filtered = orders.filter((o) => o.customer.includes(keyword));

	return HttpResponse.json({
		content: filtered.slice((page - 1) * size, page * size),
		totalElements: filtered.length,
		page,
		size,
	});
});
```

### 4.2 응답 지연 — 로딩 화면 확인용

```ts
import { delay, http, HttpResponse } from 'msw';

http.get('/api/orders', async () => {
	await delay(1200); // 1.2초 뒤 응답
	return HttpResponse.json(orders);
});
```

`delay()` 를 인자 없이 부르면 실제 네트워크처럼 들쭉날쭉한 값이 들어간다. **스켈레톤 UI 를 확인할 때 유용하다.**

### 4.3 에러 응답 — 실패 화면 확인용

```ts
// 서버 오류
http.get('/api/orders', () => HttpResponse.json({ message: '일시적인 오류입니다.' }, { status: 500 }));

// 네트워크 끊김
http.get('/api/orders', () => HttpResponse.error());
```

> **401 은 특별하다.** 인증 인터셉터가 **자동으로 토큰을 갱신하고 그 요청을 재시도**한다.
> 업무 API 목이 401 을 그냥 던지면 "갱신 → 재시도 → 또 401" 이 되어 결국 로그아웃까지 간다.
> "권한 없음"을 흉내내려면 **403** 을 쓴다.

### 4.4 요청마다 다른 응답 — 한 번만 실패시키기

```ts
let failed = false;

http.get('/api/orders', () => {
	if (!failed) {
		failed = true; // 첫 요청만 실패
		return HttpResponse.json({ message: '오류' }, { status: 500 });
	}
	return HttpResponse.json(orders);
});
```

재시도 버튼·에러 바운더리를 확인할 때 쓴다.

### 4.5 등록·수정한 값이 유지되게 하기

위 예제의 `orders` 는 모듈 변수라 **새로고침하면 초기화된다.** 그게 보통은 편하다.
F5 후에도 남아야 한다면 `localStorage` 에 둔다. 인증 목의 [`data.ts`](../src/mock-server/data.ts) 가 그 방식이다.

```ts
const DB_KEY = '__mock_orders__';

const load = (): unknown[] => JSON.parse(localStorage.getItem(DB_KEY) ?? '[]');
const save = (rows: unknown[]): void => localStorage.setItem(DB_KEY, JSON.stringify(rows));
```

> 이 키들은 **가짜 서버의 디스크**다. 앱의 저장소가 아니다.
> 개발자도구 Application 탭에서 `__mock_*` 키가 보이는 것은 정상이다.

### 4.6 특정 요청만 실서버로 흘려보내기

```ts
import { http, passthrough } from 'msw';

// 목에 잡혀 있는 경로지만 이 요청만은 진짜 서버로
http.get('/api/orders/export', () => passthrough());
```

### 4.7 한 화면·한 테스트에서만 응답 바꾸기

핸들러 파일을 고치지 않고 콘솔이나 테스트에서 잠깐 덮어쓴다.

```ts
import { worker } from '@/mock-server/browser';
import { http, HttpResponse } from 'msw';

worker.use(http.get('/api/orders', () => HttpResponse.json([]))); // 빈 목록 화면 확인
worker.resetHandlers(); // 원래대로
```

## 6. 목이 없는 프로젝트에 새로 설치하기

목을 지웠거나, 이 스캐폴드가 아닌 다른 프로젝트에 붙일 때의 절차다.

### 1) 설치

```bash
npm i -D msw
```

### 2) 서비스워커 파일 생성

```bash
npx msw init public --save
```

- `public/mockServiceWorker.js` 가 생긴다.
- `--save` 가 `package.json` 에 아래를 적어 둔다. 이게 있어야 msw 를 올릴 때 워커 파일도 같이 갱신된다.

```json
"msw": { "workerDirectory": ["public"] }
```

### 3) 기동 파일

`src/mock-server/browser.ts`

```ts
import { setupWorker } from 'msw/browser';
import { handlers } from './handlers';

export const worker = setupWorker(...handlers);

export async function startMockServer(): Promise<void> {
	await worker.start({
		// 목이 모르는 요청(Vite 모듈, 이미지 등)은 그대로 통과시킨다.
		// 기본값 'warn' 이면 콘솔이 경고로 뒤덮여 정작 봐야 할 것을 못 본다.
		onUnhandledRequest: 'bypass',

		// base 를 바꿔 배포할 수 있으므로 '/mockServiceWorker.js' 로 박지 않는다.
		serviceWorker: { url: `${import.meta.env.BASE_URL}mockServiceWorker.js` },
	});
}
```

### 4) 핸들러 모음

`src/mock-server/handlers/index.ts`

```ts
export const handlers = []; // 여기에 도메인별 핸들러를 더해 간다
```

### 5) 앱에 배선

`src/main.tsx` — **렌더보다 먼저, 첫 API 호출보다 먼저** 기동해야 한다.

```tsx
(async () => {
	if (import.meta.env.DEV) {
		const { startMockServer } = await import('./mock-server/browser');
		await startMockServer();
	}

	createRoot(document.getElementById('root')!).render(<App />);
})();
```

> **`import.meta.env.DEV` 가드와 동적 `import()` 는 둘 다 필요하다.**
> 가드만 있으면 목 코드가 번들에 남고, 동적 import 만 있으면 운영에서도 실행된다.
> 둘을 같이 써야 운영 빌드에서 `src/mock-server` 전체가 번들에서 빠진다.

### 6) 인증 목이 필요하다면 — 먼저 다시 생각한다

**스캐폴드는 인증 목을 제공하지 않는다.** 프로젝트마다 로그인 규약이 달라 그대로 쓰이는 일이
없었고, 남아 있으면 실서버가 붙은 뒤에도 조용히 앞을 가려 원인 찾기 어려운 버그를 만들었다.

서버가 한참 늦어져 정말 필요하다면 직접 만들되, 아래를 지킨다.

- 흉내낼 계약: `POST login` · `refresh` · `logout`, `GET me`.
  회전(rotation)과 **재사용 감지**까지 흉내내야 의미가 있다. 그게 없으면 회전은 그냥 번거로운 절차다.
- access token 은 서명하지 않아도 되지만 **형태(header.payload.signature)는 진짜 JWT 와 같게** 만든다.
  그래야 화면 코드가 실서버로 바뀌어도 그대로다. 검증하는 것은 **만료뿐**이면 충분하다.
- 토큰 수명은 목이 갖는다. `auth.config.ts` 에 두지 않는다 — 수명은 서버가 정하는 값이고,
  프론트 설정에 두면 목을 지운 운영 빌드에 의미 없는 항목이 남는다.
- **실서버가 뜨는 즉시 지운다.** 남겨두면 실서버를 가린다.

붙이는 절차는 [`jwt인증-공통개발자-적용가이드.md`](./jwt인증-공통개발자-적용가이드.md) 를 본다.

## 7. 테스트(Vitest)에서 쓰기

**현재 이 스캐폴드는 테스트에 목을 배선해 두지 않았다.** 필요해지면 아래처럼 붙인다.

브라우저용 `setupWorker` 는 jsdom 에서 쓸 수 없다. Node 용 `setupServer` 를 쓴다.

`src/mock-server/node.ts`

```ts
import { setupServer } from 'msw/node';
import { handlers } from './handlers';

export const server = setupServer(...handlers);
```

`src/test/setup.ts`

```ts
import '@testing-library/jest-dom';
import { server } from '@/mock-server/node';

beforeAll(() => server.listen({ onUnhandledRequest: 'bypass' }));
afterEach(() => server.resetHandlers()); // 테스트마다 덮어쓴 핸들러를 되돌린다
afterAll(() => server.close());
```

테스트 하나에서만 응답을 바꿀 때:

```ts
server.use(http.get('/api/orders', () => HttpResponse.json([])));
```

> ⚠️ `handlers/auth.ts` 는 `localStorage` 와 `crypto.randomUUID()` 를 쓴다.
> jsdom 에서 동작은 하지만 테스트끼리 목 DB 를 공유하게 되므로,
> 인증 목까지 테스트에 넣을 때는 `afterEach` 에서 `resetMockDb()` 를 함께 부른다.

## 8. 안 될 때 (Troubleshooting)

| 증상 | 원인과 조치 |
|---|---|
| 콘솔에 `[MSW] Mocking enabled.` 가 안 뜬다 | 워커가 기동을 못 했다. `public/mockServiceWorker.js` 가 있는지, `startMockServer()` 를 `await` 했는지 확인 |
| 목이 안 먹고 404 · ECONNREFUSED 가 난다 | **경로 불일치가 대부분이다.** Network 탭의 실제 요청 URL 과 핸들러 경로를 글자 그대로 비교한다 (`/orders` vs `/api/orders`) |
| 어떤 요청만 목을 못 탄다 | 그 요청이 워커 준비 **전에** 나갔다. `startMockServer()` 를 `createRoot().render()` 와 첫 API 호출보다 앞에 둔다 |
| `Detected outdated worker script` 경고 | msw 를 올렸는데 워커 파일이 옛날 것이다. `npx msw init public --save` 를 다시 돌린다 |
| 배포 경로(`/axiom/react/`)에서 워커가 404 | `serviceWorker.url` 에 `import.meta.env.BASE_URL` 을 붙였는지 확인 |
| `.env` 를 바꿨는데 그대로다 | Vite 는 `.env` 를 핫리로드하지 않는다. dev 서버 재시작 |
| 목 응답이 옛날 값으로 고정 | TanStack Query 캐시다. 목이 아니라 캐시를 의심한다. 새로고침하거나 `invalidateQueries` |
| `Set-Cookie` 가 개발자도구 Cookies 에 안 보인다 | 정상이다. MSW 는 쿠키를 브라우저 저장소가 아니라 자체 저장소(`MSW_COOKIE_STORE`)로 다룬다. **HttpOnly 쿠키 동작 자체는 실서버에서만 최종 확인된다** |
| 401 이 반복된다 | 업무 API 목이 401 을 던지고 있다. 권한 거부는 **403** 을 쓴다 (4.3 참고) |

### 콘솔에서 쓸 수 있는 것

```js
__auth.me(); // 인증 인터셉터를 타는 요청을 쏜다 (401 -> 자동 갱신 -> 재시도 확인용)
```

`__auth` 는 [`src/shared/auth/dev-probe.ts`](../src/shared/auth/dev-probe.ts) 가 등록한다.
**기본 상태에서는 등록되지 않는다** — `main.tsx` 에서 `registerAuthDevProbe()` 를 켜야 생긴다.

## 9. 지켜야 할 규칙

| 규칙 | 이유 |
|---|---|
| **목은 앱 코드를 import 하지 않는다** | 가짜 서버가 앱을 부르면 의존 방향이 거꾸로다. 실서버가 생겨 폴더를 지울 때 앱 쪽이 딸려 깨진다 |
| **업무 API 목은 실서버가 생기면 지운다** | 목이 남아 있으면 실서버 응답을 가로채 "서버는 고쳤는데 화면은 옛날 값"인 상황이 생긴다. 이게 제일 찾기 어렵다 |
| **인증 핸들러(`handlers/auth.ts`)는 함부로 고치지 않는다** | 그건 목이 아니라 **실서버와 맞춘 계약**이다. 고치면 실서버로 갈아탈 때 화면이 깨진다 |
| **토큰 수명 같은 "서버가 정하는 값"은 목이 갖는다** | `auth.config.ts` 에 두면 프론트가 토큰 수명을 정한다는 잘못된 신호가 되고, 목을 지운 운영 빌드에 의미 없는 항목이 남는다 |
| **목 데이터에 실제 개인정보·운영 데이터를 넣지 않는다** | `src/` 는 레포에 그대로 커밋된다 |

## 10. 실서버로 갈아탈 때

1. `.env` 의 `VITE_SERVER_URL` 을 실서버 주소로 바꾼다.
2. 완성된 API 부터 `handlers/index.ts` 에서 하나씩 뺀다. (뺀 경로는 자동으로 실서버로 나간다)
3. 전부 뺐으면 [`src/mock-server/README.md`](../src/mock-server/README.md) 의 삭제 절차 4단계를 따른다.
4. **`public/mockServiceWorker.js` 를 잊지 않는다.** `public/` 은 빌드할 때 `dist/` 로 그대로 복사되므로,
   목을 안 쓰더라도 이 파일은 운영 산출물에 딸려 나간다. 동작하지는 않지만 배포물 점검에서 지적될 수 있다.

`src/shared/auth/**` 와 `src/config/auth.config.ts` 는 **건드리지 않는다.**
목이 실서버와 같은 계약을 흉내내고 있으므로 주소만 바꾸면 그대로 붙는다.
