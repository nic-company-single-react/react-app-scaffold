## 1. 왜 가이드가 필요한가

지금 인증 문서는 `src/shared/auth/README.md` 하나이고, **독자가 한 명이라고 가정하고 쓰였다.**

실제 독자는 둘이고 필요가 겹치지 않는다.

- **공통 개발자**는 "서버에 맞춰 어떻게 세팅하나"가 필요한데, 설계 이유가 섞여 있어 읽을 게 두 배다.
- **업무 개발자**는 "내 화면에서 뭘 해야 하나"가 필요한데, **그 내용이 아예 없다.**

업무 개발자가 지금 문서를 열면 `strategy` · `extractAccessToken` · 서버 요구 조건 같은 **자기와 상관없는 것**을 먼저 만난다. 그러면 읽지 않고, 읽지 않으면 각자 401 분기를 짜 넣는다.

**스캐폴드가 "처리하지 않아도 되는 상태"를 만들어놨는데 그걸 모르는 게 가장 큰 손실이다.**

---

## 2. 독자 둘 — 무엇이 다른가

| | 공통 개발자 | 업무 개발자 |
|---|---|---|
| 언제 읽나 | 프로젝트 착수 시 **한 번** | 업무 개발 중 **필요할 때마다** |
| 인원 | 1~2명 | 5~20명 |
| 목적 | 서버에 맞춰 붙이고 검증한다 | 내 화면에 인증이 어떻게 걸리는지 안다 |
| 고치는 파일 | `.env` · `auth.config.ts` · `domains/auth/types.ts` · 로그인 화면 · `shared/router` | **없다** (읽기만 한다) |
| 알아야 할 개념 | 전략 3개 · 확장 지점 3개 · 서버 계약 | 훅 3개 · 라우트 보호 · **내가 안 해도 되는 것** |
| 문서 형태 | **절차 체크리스트** (위→아래로 한 번) | **레시피 + FAQ** (검색해서 찾아 읽음) |
| 잘못됐을 때 | 로그인 자체가 안 됨 → 바로 안다 | **조용히 잘못 짠다** (각자 401 처리, 토큰 직접 첨부) |

**형태가 다르다는 게 핵심이다.** 한 문서에 넣으면 둘 다 나빠진다.

## 3. 업무 개발자가 실제로 던지는 질문

가이드 목차의 원재료다. **절반 이상이 "안 해도 된다"가 답**이라는 게 이 목록의 특징이다.
추측이 아니라 구현하면서 실제로 밟은 함정들이라 그대로 FAQ 항목이 된다.

### 3.1 API 호출

- 내 화면에서 API 부를 때 **토큰을 직접 붙여야 하나?** → 아니다. 요청 인터셉터가 붙인다
- **401이 나면 내가 처리해야 하나?** → 아니다. 자동 갱신 후 재시도된다. 호출 측은 성공만 본다
- 그럼 내 `catch` 는 언제 도나? → 갱신까지 실패했을 때. 그때는 이미 로그인 화면으로 가고 있다
- `useApi` / `callApi` 쓸 때 뭘 더 해야 하나? → 없다
- 파일 다운로드처럼 **axios를 안 타는 요청**은? → `getAccessToken()` 으로 직접 붙인다 (유일한 예외)
- 로그인 없이 부를 수 있는 공개 API 는 어떻게 하나?

### 3.2 사용자 정보 · 권한

- 로그인한 사람의 **이름 · 부서 · 사번을 어디서 가져오나?** → `useAuth<IAppUser>()`
- 사용자 타입에 필드를 추가하려면? → 공통 개발자에게 (서버 응답과 맞물린다)
- **권한별로 버튼 · 메뉴를 감추려면?** → `hasRole('admin')`
- 화면 전체를 권한으로 막으려면? → `<ProtectedRoute roles={[...]} />` (공통 개발자와 협의)
- 권한 이름은 어디서 정해지나?

### 3.3 라우팅

- 내가 만든 화면을 **로그인 필수로 하려면?** → `shared/router/index.tsx` 의 보호 구간에 넣는다
- 이미 보호 구간이면 내 화면은 아무것도 안 해도 되나? → 그렇다
- 로그인 안 한 사람에게도 보여야 하는 화면은?
- 화면 안에서 "로그인 안 됨"을 직접 체크해야 하나? → 보호 구간 안이면 불필요

### 3.4 개발 중 일상

- **개발할 때 로그인은 어떻게 하나?** → 목 계정 `admin` / `admin1234`, `user` / `user1234`
- **새로고침하면 로그인이 풀리는데 정상인가?** → 아니다. 유지돼야 한다. 안 되면 공통 개발자에게
- Network 탭에 `refresh` 요청이 자꾸 보이는데 정상인가? → 목 토큰 수명 설정 문제 (§9 해결됨)
- 토큰을 콘솔에서 보려면?
- 로그아웃 버튼을 내 화면에 넣으려면? → `useLogout()`
- 실서버가 아직 없는데 내 업무 API 는? → **목은 인증만 흉내낸다.** 실서버가 생길 때까지 화면만 (§9 결정)

### 3.5 화면 흐름

- 로그인 직후 내 화면이 초기 데이터를 불러야 하는데 **순서가 어떻게 되나?**
- 로그아웃하면 내가 캐시해둔 데이터는? → 쿼리 캐시가 통째로 지워진다
- 다른 탭에서 로그아웃하면 내 화면은?

### 3.6 문제가 생겼을 때 (트러블슈팅 원재료)

- 화면이 자꾸 로그인으로 튄다
- 로그인은 되는데 그다음 요청이 전부 401
- 내 API만 401이 난다
- 로그인 화면이 새로고침 때마다 번쩍인다

## 6. 가이드 작성 전 조치 (완료)

가이드를 쓰기 전에 **문서로 설명해야 할 결함**을 먼저 없앴다. 문서가 아무리 좋아도 코드가 어긋나 있으면 그걸 먼저 믿는다.

### 6.1 목 토큰 수명을 `.env` 로 뺐다

`ACCESS_TTL_MS` 가 `src/mock-server/tokens.ts` 에 **20초로 하드코딩**돼 있었다. 검증에는 좋았지만 업무 개발자는 개발 내내 20초마다 갱신을 보게 되어 "이게 정상인가"를 계속 묻게 된다.

```
.env  VITE_MOCK_ACCESS_TTL_SEC=1800    기본 30분 — 평소 개발. Network 탭이 조용하다
                                = 20   "만료 → 자동 갱신 → 재시도" 를 눈으로 확인할 때
```

> **`auth.config.ts` 에 두지 않았다.** 토큰 수명은 **서버가 정하는 값**이다. 프론트 설정에 두면
> "우리가 토큰 수명을 정한다"는 잘못된 신호가 되고, 목을 지운 운영 빌드에 아무 의미 없는 항목이
> 남는다. **목의 값은 목이 갖는다.**

### 6.2 깨져 있던 예제 화면을 고쳤다

`.env` 의 baseURL 을 `/api` 로 바꾼 뒤 `domains/example` 의 useApi 데모가 `/api/posts` 를 부르는데 목에 핸들러가 없어 **404** 였다. 업무 개발자가 "API 호출 예제"로 처음 열 화면이다.

`src/mock-server/handlers/example.ts` 에 데모 데이터 핸들러를 뒀다.
**업무 API 지원이 아니다** — 스캐폴드 자체 예제가 인터넷 없이도 돌게 하는 것이 목적이고 딱 그만큼이다.

## 7. 문서 구성 — Docusaurus 전제

### 산출물

```
plan/jwt인증-공통개발자-적용가이드.md    세팅 절차 (한 번 읽는 체크리스트)
plan/jwt인증-업무개발자-사용가이드.md    레시피 + FAQ (찾아 읽는 레퍼런스)
```

레포의 md 가 **원본**이고, Docusaurus 사이트는 이것을 옮겨 배포한다.
폐쇄망에서는 가이드 사이트에 접근이 안 될 수 있으므로 **레포 안에서도 그대로 읽히는 상태**를 유지한다.

### Docusaurus 로 옮길 것을 전제로 지킬 것

| 규칙 | 이유 |
|---|---|
| **md 하나 = 사이드바 항목 하나.** 문서를 잘게 쪼개지 않는다 | 업무 개발자는 검색해서 한 페이지 안에서 찾는다. 쪼개면 왕복이 는다 |
| **`#` 제목은 문서당 하나**, `##` 이 사이드바 목차가 된다 | Docusaurus 가 `##` 로 우측 목차를 만든다. 계층을 얕게 |
| **코드 경로는 링크가 아니라 텍스트**로 쓴다 (`src/config/auth.config.ts`) | 사이트에서는 레포 상대링크가 깨진다 |
| 두 가이드 사이 상호 링크만 상대경로로 | 옮길 때 이 둘만 고치면 된다 |
| **화면 캡처를 넣지 않는다** | 프로젝트마다 화면이 다르다. 캡처는 바로 거짓말이 된다 |
| 코드 블록에 언어 지정(`ts` · `tsx` · `bash`) | 사이트 하이라이팅 |
| 문서 맨 위에 **대상 독자 한 줄** | 사이트에서는 검색으로 바로 들어와 앞뒤 맥락이 없다 |

> 이관 자체는 나중이지만 **글은 지금부터 그 형태로 쓴다.** 나중에 고치면 두 번 쓴다.

## 9. 인수인계 템플릿 (공통 → 업무)

공통개발자 가이드 6번에 들어갈 **복사해서 보내는 공지**다.
**공통 개발자가 채워 넣는 자리(4·5·6번)를 비워두는 게 핵심**이다. 그래야 프로젝트마다 실제 값이 들어간다.

```
[인증 세팅 완료 공지]

1. 로그인 화면:  /#/auth/login
2. 개발용 계정:  admin / admin1234   (관리자)
                 user  / user1234    (일반)
3. 여러분이 할 일은 없습니다.
   - API 호출 시 토큰을 붙이지 마세요 (자동)
   - 401 처리를 짜지 마세요 (자동 갱신 + 재시도)
   - 로그인 상태를 따로 스토어에 만들지 마세요 (useAuth 사용)
4. 사용자 정보:  const { user } = useAuth<IAppUser>();
```

## 10. 남은 결정 3개

| # | 결정할 것 | 메모 |

## 11. 합격 기준 — 가이드가 좋은지 어떻게 아는가

분량으로 판정하지 않는다. **리허설로 판정한다.**

1. **공통 개발자 리허설** — 인증을 모르는 사람이 가이드만 보고 `strategy` 를 `'storage'` 로 바꿨다가 `'cookie'` 로 되돌리는 왕복을 할 수 있는가. 중간에 `src/shared/auth` 안쪽을 열어야 했다면 **그 부분이 문서에서 빠진 것**이다.
2. **업무 개발자 리허설** — 새 화면 하나에 "로그인한 사용자 이름 + 권한별 버튼 + API 호출"을 붙이는 데 **가이드 한 페이지만** 보면 되는가.
3. **"안 해도 되는 것"이 전달됐는가** — 리허설한 업무 개발자가 401 분기나 토큰 첨부 코드를 짰다면 실패다.
4. **§3 · §4 의 질문에 전부 답이 있는가** — 목차만 훑어서 답의 위치를 찾을 수 있어야 한다.
